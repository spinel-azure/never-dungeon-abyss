# AURORA OS 三女神戦への接続

2026-10-31。Lv100地図迷宮の三女神戦で、既存の遭遇表示の後に起動演出→召喚ログ→既存の戦闘開始処理を実行する。

- 接続位置：`js/main.js` の `beginV2Battle()`。`startBattle()` を演出終了まで呼ばないため、戦闘初期化・NPC援護・先制処理・ターン進行は演出後に実行される。既存の戦闘開始オプションは維持。
- 対象判定：特殊地図ボスのsource、mapLevel=100、context.bossIdと敵IDの一致、`isSuperGoddess()`によるID／テーマ／Candidate／Lvの検証。名前では判定しない。
- 分岐：`combat/hacking-device.js` の `canActivateHackingDevice()` を戦闘側と演出側で共用。転生3回＋所持の条件を演出開始の準備時に一度だけ評価する。
- 効果の適用：従来どおりbattle-engineのみ。開始HP5％減少、雷10％軽減、月相加算半減、準備回復・再生25％減少の数値変更なし。演出は能力を変更しない。
- 統括：`js/aurora-battle-intro.js`。2つのモーダルの下に覆いを保ち、切替時にゲーム画面を露出させない。キーボードの押下状態とゲームパッドAの立ち上がりを通しで管理し、本体のゲームパッド配送を遮断する。最終暗転後は入力を離して300ms経過してから戦闘を開始する。
- 地図の描画更新・通常入力・受動通知を演出中停止。プレイ時間の計測は継続する。
- 保存：新規の永続項目なし。`battleOpening` は二重呼出し防止の一時状態で、既存シリアライザには保存しない。遭遇情報は演出前の既存保存で保持。演出途中のページ離脱は戦闘を開始せず、再読込後に遭遇から演出を再生する。
- 戦闘チェックポイントがある中断再開では演出を省略し、従来の `resumeBattleState` をそのまま渡す。弱体化の再適用も行わない。
- 起動画像の読込失敗・タイムアウトは既存のbootのfalse結果を受けて召喚ログへ進む。ページ離脱によるcancelは戦闘へ進まない。
- 音声：探索BGMを継続し、従来の戦闘BGM切替を演出後に実行。専用SEは未接続。将来は既存audioのURL登録に専用キーを追加し、統括側から `playSe(key)` を呼べる。終了待ちが必要なら `playSeToEnd(key)` を使用し、独立したAudioを生成しない。

## 検証

`tests/aurora-battle-intro.test.mjs` は対象外除外・三女神全種・転生0～3・所持条件・チェックポイント除外を検証。既存 `tests/hacking-device.test.mjs` で弱体化の数値と再開互換性を検証。

`tests/browser/aurora-battle-intro.mjs` は実際のmain.jsの地図遭遇と保存経路を使い、通常／ハッキング／低転生所持、キーボード押下継続、タッチ、模擬ゲームパッド、演出中の戦闘未初期化、HP/SP/NPC状態の維持、開始回数、ページ離脱後の演出再開、戦闘チェックポイント再開、黄金郷の対象外動作を検証する。画像はTEMPへ保存する。

iPhone実機・物理ゲームパッドは未確認。PCブラウザのタッチ・ゲームパッド入力エミュレーションによる確認。

最終結果：Node全件2,242件成功・失敗0件。本編ブラウザ検証は1280pxのルミナ通常／ノクティア干渉、390pxのゼレーナ干渉／転生2回ルミナ通常、768pxの黄金郷対象外、および画像欠落時の継続・ポインター押下中の待機が成功。起動・召喚の単体ブラウザ回帰検証も1280／768／390pxで成功。並列実行時に既存通知テスト2件の短時間待機が時間切れになったため、ブラウザ検証の終了後に全件を再実行し、上記の成功を確認した。

## 将来のV3接続

演出の共通入口は `js/aurora-battle-intro.js` の `getAuroraBattleRoute(character, enemy, {mapBoss, resumed})` と `createAuroraBattleIntro({anchor}).play({route, isCurrent, startBattle})`。V2のsource文字列やセッション構造には依存しない。V2固有の検証だけを `js/special-map/aurora-v2.js` の `getV2AuroraBattleRoute()` に置く。

V3実装時は以下を追加接続する。V3の戦闘処理や保存項目は今回作成しない。

1. V3側で正式な遭遇ID・地図レベル・ボスIDを照合し、地図ボスであることを確認して `mapBoss:true` を渡す。通常奈落や未検証の遭遇でtrueにしない。共通側でも既存の三女神識別を検証する。
2. V3の戦闘チェックポイントを検証・復元して `resumed` に渡す。復元済みならルートはnullとなり、演出を省略する。
3. 戦闘対象を確定・保存した後、戦闘初期化より前に共通playをawaitする。既存の戦闘開始関数を `startBattle` コールバックで渡し、後から別途重ねて呼ばない。`isCurrent` はV3の有効なセッションと遭遇IDを照合する。
4. 共通コントローラーの `isActive()` をV3の更新停止・入力遮断に接続する。本体のゲームパッド配送は遮断し、Aの物理入力は共通側に任せる。
5. V3の中断保存では演出フラグではなく、確定済みの遭遇と戦闘チェックポイントを使用する。新規戦闘の弱体化は既存battle-engine、再開は既存resume経路へ委ねる。

共通関数は弱体化・セーブ・戦闘状態を変更しない。V3で敵のデータ形式が変わる場合は、既存の `isSuperGoddess()`／戦闘エンジンが受け取れる戦闘用データへ変換してから渡す。
