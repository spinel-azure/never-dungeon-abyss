# QA成果物の保存方針（開発内部向け）

2026-09-26確認：Git追跡対象のartifacts/は620ファイル、217,052,824bytes（約207MiB）。追跡済み全ファイルの作業ツリー上の合計は337,254,638bytes。この値は.git履歴や未追跡ファイルを含まない。「ゲーム本体42MB」とは集計範囲が異なる。

## 今後の保存先

- 通常のローカル検証画像・生ログ：OS一時フォルダまたはリポジトリ外のQA用フォルダ。今回のinventory-sort.mjsはOS一時フォルダへ出力する。一時フォルダは永続保管に使わない。
- Gitに残すもの：再実行可能なテストコード、精査台帳の要約、判断根拠として必要な小さな比較データ・レポート。代表画像は必要性を確認して選ぶ。
- 全画像・ログの継続保管：今後CIで生成する場合はActions Artifact等への出力を検討。公開可否、保存期限、サイズ上限を決めてから設定する。重要な長期資料は別途保管する。
- Release添付は、版に紐づけて長期保存したい選別済み資料の候補。毎回の検証ログを無条件に公開添付しない。

## 既存成果物の整理手順（未実施）

1. artifacts内を画像・ログ・小さな比較データ・実装レポートに分類し、docs/tests等からの参照を確認する。
2. 残す代表資料と、退避する再生成可能な成果物の一覧を作る。
3. リポジトリ外へコピーし、ファイル数・サイズ・ハッシュを確認する。
4. 退避と参照修正を確認してから、合意した対象をGit追跡から除外する。テストの旧出力先も段階的に変更する。
5. 履歴の書き換えは通常整理と分離する。最新ツリーから削除しても過去コミットの容量は残るため、cloneサイズ削減には別の検討が必要。

今回は既存成果物の削除、追跡解除、履歴書き換え、外部アップロード、CIの変更は行っていない。既存ブラウザテストにはartifacts/へ書くものが残るため、再実行時に出力先を確認する。

## 統合層の分割

main.jsの責務肥大化は保守上のリスクであり、行数だけで動作不良とは判断しない。今後の追加処理は専用モジュールへ置く。既存処理は入口/町遷移など一責務ずつ、入力停止・BGM・保存/ロード・帰還の契約と回帰テストを先に確認して分割する。今回のソート規則はdata/inventory-sort.jsに配置し、main.jsへ追加しない。
